# tiny-dev-lab 커리큘럼 품질 기준

이 기준은 TypeScript, React, Next.js, NestJS, Prisma, Jest + React Testing Library, Redis를 포함한 모든 기술 스택 과정에 적용한다. 스택별 필수 단계는 이 공통 기준 위에 추가한다.

커리큘럼 작업은 [커리큘럼 하네스 에이전트 운영 방식](./harness-agent-workflow.md)에 따라 역할별 에이전트에 분리한다. 루트 에이전트는 결과를 통합하고, 구현과 검증은 서로 다른 역할이 맡는다. 작업마다 실제 agent, 모델, 플러그인, 스킬, 산출물과 검증 근거를 기록한다.

## 판단 순서

커리큘럼은 다음 순서로 설계하고 평가한다.

1. 대상 학습자를 정한다.
2. 수료 후 학습자가 직접 할 수 있어야 하는 일을 정한다.
3. 선수 지식에서 수료 목표까지 이어지는 학습 순서를 정한다.
4. 각 단계에 필요한 실습을 배치한다.
5. 중복, 누락, 난도 상승과 반복 연습을 검토해 실습 수를 결정한다.
6. 그 뒤에 각 레슨의 제목, 설명, 과제와 답안 검사를 다듬는다.

레슨 수를 먼저 정한 뒤 내용을 채우지 않는다. `36개`, `40개` 같은 숫자는 목표가 아니다. 수료 목표를 달성하는 데 필요한 실습을 배치한 결과여야 한다.

## 1. 대상 학습자

과정마다 다음을 구체적으로 적는다.

- 이미 작성해 본 코드와 프로젝트 경험
- 반드시 알아야 하는 선수 지식
- 이 과정을 찾게 되는 실제 개발 상황

`초보자`, `개발자`만으로는 부족하다. 예를 들어 “JavaScript 함수와 객체는 작성할 수 있지만 외부 API 응답을 TypeScript에서 안전하게 다루지 못하는 웹 개발 학습자”처럼 시작점이 보여야 한다.

## 2. 수료 후 도착점

수료 목표는 `이해한다`, `학습한다`로 끝내지 않는다. 새 코드나 오류 상황에서 확인할 수 있는 행동으로 쓴다.

- 무엇을 작성하거나 수정하는가
- 어떤 잘못된 입력이나 사용을 거절하는가
- 실행 결과나 타입 오류를 어떻게 확인하는가
- 선택한 방법의 이유와 한계를 설명할 수 있는가

최소 세 개의 수료 행동을 두며, 각 행동은 하나 이상의 학습 단계와 연결한다.

## 3. 과정 흐름

각 단계에는 제목, 이 위치에 놓인 이유, 연결된 수료 목표, 포함할 공개 실습 ID가 필요하다. 모든 정식 실습은 정확히 한 단계에 속하고 실제 공개 순서와 일치해야 한다. 선택 진단은 실습 수와 수료 분모에서 제외할 수 있지만 제외 사실을 검사 결과에 표시한다.

평가할 때 다음을 확인한다.

- 선수 지식 없이 새 개념이 갑자기 등장하지 않는가
- 앞 실습의 결과를 다음 실습에서 사용할 수 있는가
- 문법 연습에서 실제 기능 적용으로 난도가 자연스럽게 올라가는가
- 캡스톤이 앞에서 배우지 않은 핵심 개념을 새로 요구하지 않는가
- 비슷한 실습이 새 학습 행동 없이 반복되지 않는가

## 4. 실습 수의 적절성

과정마다 권장 최소·최대 실습 수와 근거를 기록하고 다음 중 하나로 판정한다.

- `approved`: 현재 수가 목표와 흐름에 적절하다.
- `revise`: 현재 수가 범위 안에 있더라도 통합, 분리, 추가 또는 삭제가 필요하다.
- `pending`: 아직 평가하지 않았다. 품질 검사는 실패한다.

판정에는 다음 근거가 필요하다.

- 각 수료 목표를 실제로 연습하는 실습이 있는가
- 중요한 행동은 새 상황에서 다시 적용해 볼 기회가 있는가
- 한 실습에 서로 다른 핵심 개념이 너무 많이 섞이지 않았는가
- starter가 핵심 답을 이미 제공해 형식적인 수정만 남기지 않았는가
- 같은 문법을 반복하는 실습은 서로 다른 관찰 결과나 통합 목적이 있는가
- 전체 예상 시간과 장별 난도에 비해 실습 수가 과하거나 부족하지 않은가

자동 하네스는 수, 연결, 순서, 누락과 명시된 판정을 검사한다. 설명이 설득력 있는지와 실제 학습 효과는 편집 평가와 학습자 관찰로 판단한다. 자동 통과를 사람의 평가로 대신하거나 사람의 평가를 글자 수 검사로 대신하지 않는다.

프로젝트의 검사 스크립트, 테스트와 fixture는 저장소 하네스다. 플러그인이나 스킬과 구분한다. 스킬은 작업 방식을 돕고, 반복해서 강제해야 하는 기준은 fixture와 자동 테스트에 남긴다.

## 5. 레슨 품질

과정 구조가 정해진 뒤 각 레슨에서 다음을 확인한다.

- 제목과 요약에서 학습 주제를 바로 알 수 있다.
- 실무에서 언제 쓰는지 구체적인 코드 상황을 설명한다.
- 문제, 필요한 개념, 흔한 실수, 성공 결과를 설명한다.
- 과제는 설명한 개념을 직접 연습한다.
- starter와 solution의 차이가 학습 목표에 해당한다.
- 그럴듯한 오답이 타입 또는 실행 검사에서 실패한다.
- 통과 후 설명과 면접 질문은 방금 한 코드 선택의 이유와 한계를 다룬다.
- 레슨 주제에 직접 대응하는 공식 문서 출처가 있다.

한국어 문장은 [개발자 학습 콘텐츠 UX 라이팅 프롬프트](./developer-ux-writing-prompt.md)를 기준으로 작성하고 검토한다. 사용자가 완성 문구를 제공하면 해당 문구를 우선한다.

## 하네스 입력과 결과

프로젝트 과정은 `src/curriculum/index.ts`에서 `course`와 `lessons`를 내보낸다. fixture는 같은 구조의 `course`와 `lessons`를 가진다. 공통 `course` 필드는 다음 정보를 담는다.

- `audience.description`, `audience.prerequisites`
- `completionOutcomes`
- `flow[].rationale`, `flow[].outcomeRefs`, `flow[].lessonIds`
- `practicePlan.minimum`, `maximum`, `rationale`, `decision`

`npm.cmd run test:curriculum-quality`은 과정 구조와 레슨 형식을 함께 검사한다. 결과에는 공개 레슨 ID, 검사한 실습 수, 제외한 진단 수, 실습 수 평가 상태와 권장 범위가 출력된다.

새 스택을 추가할 때 이 공통 입력을 생략할 수 없다. Next.js의 환경 설정·사이트 구축·배포처럼 스택에 필요한 단계는 `stackProfiles`에 별도로 추가한다.
